## 1. Что умеет сток (и чего не умеет)

Стоковый `calcdamage.f` — это **индикатор инициации разрушения без
эволюции**. Одна скалярная переменная на точку интегрирования:

```
omega_D  +=  d(eps_p) / eps_f(eta, T, d(eps_p)/dt)
```

с двумя критериями предельной пластической деформации:

* **Rice–Tracey**  `eps_f = 1.65 * eps0 * exp(-3*eta/2)`
* **Johnson–Cook** `eps_f = (d1 + d2*exp(-d3*eta)) * (1 + d4*ln(pdot/pdot0)) * (1 + d5*That)`

где `eta = sigma_m / sigma_vm` — трёхосность, `That` — гомологическая
температура. Когда `omega_D > omega_lim`, элемент **мгновенно удаляется**:

```fortran
dam(jj,i) = dam(jj,i) + dpeq/ef
if(dam(jj,i).gt.xlimit) then
  ipkon(i) = -ipkon(i) - 2      ! элемента больше нет
  exit
endif
```

Физические следствия, важные для доклада:

1. **Между «целым» и «удалённым» ничего нет.** Нет закона размягчения,
   нет деградации жёсткости, напряжение падает с полного до нуля за один шаг.
2. **Удаление не связано ни с какой энергией разрушения.** Диссипация
   определяется тем, сколько энергии случайно оказалось в удалённом элементе,
   то есть **зависит от размера элемента** без всякой компенсации.
3. **Нет внутренней длины** → посткритическая ветвь сеточно-зависима
   (локализация в один слой элементов).
4. **Нет никакой регуляризации** — ни вязкой, ни нелокальной.
5. **Нет когезионных элементов** — межфазное разрушение описать нечем.
6. **Нет топологического контроля** после удаления: оторвавшийся островок
   материала остаётся в системе уравнений и делает оператор сингулярным.

Модуль в этом дереве закрывает все шесть пунктов.

## 2. Объёмная модель: DE1 / DM2 — двухстадийное вязкое разрушение

Файлы: `calcdamage.f`, `resultsmech.f`, `damageinitiations.f`,
`damsnapcheck.f`.
Активируется параметром `EVOLUTION=DISPLACEMENT` на карте
`*DAMAGE INITIATION` (`damageinitiations.f:68`). Без него поведение —
**побитово стоковое**.

### 2.1 Стадия 1 — инициация

Как в стоке, накопительный индикатор

```
omega_D = integral  d(eps_p) / eps_f(eta)
```

но локус разрушения `eps_f(eta)` можно задать **таблично** — критерий
`CRITERION=DUCTILE` (DM2.0), новый по отношению к стоку:

```
*Damage Initiation, Criterion=Ductile, Evolution=Displacement, Npoints=6
omega_lim, u_f, eta_1, eps_f_1, eta_2, eps_f_2, ...
```

Интерполяция линейная по `eta`, за пределами таблицы — обрезание по крайним
точкам (`calcdamage.f:1020`, `dm2failurestrain`). Монотонность `eta_i`
проверяется при чтении (`damageinitiations.f:239`). Это та же форма, что
используют в Abaqus для ductile damage: кривая `eps_f(eta)`, снятая из
экспериментов на разной трёхосности.

Второй новый вариант — старый Rice–Tracey **плюс** эволюция: тогда карта
несёт четыре константы `eps0RT, omega_lim, u_f` вместо трёх, и наличие
четвёртой и есть признак, по которому включается новый путь
(`calcdamage.f:480`). Johnson–Cook с `EVOLUTION=DISPLACEMENT` пока
запрещён явной ошибкой.

Инициация считается достигнутой при `omega_D = 1` (жёстко требуется
`omega_lim = 1`, `damageinitiations.f:209`) — дальше стадия 2.

### 2.2 Стадия 2 — эволюция по пластическому перемещению (crack band)

Это главное физическое добавление. После инициации повреждение растёт не по
деформации, а по **пластическому перемещению**:

```
D += L * d(eps_p) / u_f                          calcdamage.f:701, 976
```

где

* `u_f` — задаваемое **перемещение при разрушении** (мм), карта
  `*DAMAGE INITIATION`;
* `L` — характерная длина элемента, для линейного тетраэдра
  `L = (6 V0)^(1/3)` по **отсчётной** конфигурации (`calcdamage.f:301`,
  `calcdamage.f:930`).

Это регуляризация Хиллерборга / crack band (Bažant–Oh): удельная энергия
разрушения на единицу площади

```
G_f  ~  sigma_y * u_f     (не зависит от L)
```

получается постоянной, потому что деформация размягчения масштабируется
как `u_f / L`. Именно это чинит первый дефект стока — сеточную зависимость
**диссипации**.

Момент пересечения `omega_D = 1` внутри шага не «съедается»: доля шага
`alpha_i = (1 - omega_base)/dOmega` вычисляется явно, и на эволюцию идёт
только остаток `(1 - alpha_i) * d(eps_p)` (`calcdamage.f:727-733`).

Ограничение реализации: **только C3D4** — иначе `*ERROR` (`calcdamage.f:250`,
`calcdamage.f:905`). Причина названа в коде: определение характерной длины
для других типов элементов неоднозначно.

### 2.3 Деградация напряжений и жёсткости

В `resultsmech.f` (после штатного возврата на поверхность текучести,
`resultsmech.f:1241`):

```
g = 1 - D                                        (скалярная деградация)
sigma      = g * sigma_eff
C          = g * C_ep
```

`mechmodel`/`incplas` не трогаются вообще — деградация вынесена наружу
упругопластического обновления, поэтому стоковый return mapping остаётся
побитово тем же.

### 2.4 Остаточная жёсткость `gmin`

```
if (g < gmin) g = gmin                           resultsmech.f:1253
```

по умолчанию `gmin = 1e-4`, переопределяется `CCX_DAMAGE_GMIN`. Физический
смысл — не дать оператору выродиться, пока элемент ещё в сетке. Комментарий
в коде честно называет цену: в процессной зоне таких элементов тысячи
одновременно, и оператор становится плохо обусловленным; порог — торговля
«немного невыпущенной нагрузки» против обусловленности.

### 2.5 Вариант с сохранением сжатия (`CCX_DAMAGE_COMPRESSION=1`)

По умолчанию деградируется **весь** тензор. Опционально — только
девиатор и растягивающая гидростатика, сжимающая гидростатика не
деградируется (`resultsmech.f:1299`):

```
K'  = K                  (модуль объёмного сжатия сохраняется)
mu' = g * mu             (сдвиговой деградируется)
E'  = 9*K*g*mu/(3*K + g*mu)
nu' = (3*K - 2*g*mu) / (2*(3*K + g*mu)),   nu' <= nu_max (0.45 по умолчанию)
```

Мотивация в коде: трещиноватый элемент всё ещё держит сжатие после закрытия
трещины (ссылка на Abaqus Verification Guide 2.2.21-V), и **когезионный
закон в этом же дереве уже так делает** — «compression retains the full
normal penalty», `cohesive_uc6.f:236`. То есть это устранение
несогласованности между объёмным и межфазным законами. Ограничение `nu_max`
нужно потому, что при `mu -> 0` и сохранённом `K` материал становится
несжимаемым, а линейный тетраэдр в этом пределе **запирается**.

### 2.6 Упаковка переменной состояния

Один массив `dam` несёт обе стадии (`calcdamage.f:672`):

```
0 <= dam < 1   :  dam = omega_D          (инициация)
1 <= dam <= 2  :  dam = 1 + D            (эволюция)
```

Физическая переменная деградации — `D = max(0, dam - 1)`. Смысл: вывод
`DUCT` остаётся монотонным и не понадобился новый глобальный массив истории.

### 2.7 Транзакционность (почему это физика, а не бухгалтерия)

Появились режимы `imode` (`calcdamage.f:88`):

* `imode = 0` — **предиктор**: не меняет `dam`/`ipkon`, а только считает,
  сколько элементов пересечёт предел за этот физический шаг и на какой доле
  `alphaevent` это случится впервые (локатор события);
* `imode = 1` — применение со стоковым жёстким удалением;
* `imode = 2` — пробное обновление от **неизменяемой базы** `dambase` —
  состояния на начало физического шага.

`dambase` существенна: `xstate - xstateini` охватывает весь физический шаг,
поэтому прибавлять этот приращение к уже обновлённому `dam` означало бы
**двойной счёт пластической деформации** при переравновешивании на той же
нагрузке. С `dambase` повреждение пересобирается заново на каждой итерации
Ньютона, и откат отменённой попытки корректен по построению.

## 3. Вязкая регуляризация (Duvaut–Lions)

Один и тот же закон применён и к объёму, и к когезии.

```
dDv/dt = (D - Dv) / eta
```

Неявная схема (обратный Эйлер) даёт ровно то, что стоит в коде:

```
beta = dt / (eta + dt)
Dv   = Dv_committed + beta * (D - Dv_committed)
Dv   монотонна: Dv >= Dv_committed   (разгрузка не «лечит» точку)
```

* объём: `resultsmech.f:1220-1231`, параметр `eta` — переключатель
  `CCX_DAMAGE_VISCOSITY`;
* когезия: `cohesive_uc6.f:197-203`, параметр `mu` — **шестая константа
  `*USER SECTION`**, то есть часть материальной карты.

Что это делает физически. Хрупкая фаза, разрушающаяся внутри вязкой,
проскакивает через **структурную предельную точку**: управление
перемещением захвата не управляет локальным событием, потому что
окружающая матрица работает как мягкая пружина последовательно. Релаксация
переменной деградации делает размягчение скорость-зависимым и убирает
предельную точку.

Ключевое свойство реализации: **`D` продолжает эволюционировать от
зафиксированной базы с физической скоростью**; задерживается только та
жёсткость, которую видит сборка. Значит, закон эволюции и диссипируемая
энергия разрушения не трогаются; `eta = 0` воспроизводит невязкую ветвь
точно.

Побочный эффект, который пришлось измерить и исправить: напряжение
масштабируется на `1 - Dv`, поэтому **триггер удаления обязан читать ту же
переменную**. Пока он читал `D`, элементы удалялись, неся до 41 %
эффективного напряжения (`batch_Dvis` до 0.592), и эта нагрузка
высвобождалась за один шаг при постоянной нагрузке. Исправление сдвинуло
расчёт с `lambda=0.3793` до `0.4651` (`nonlingeo.c:1519`,
`CCX_DAMAGE_DELETE_VISC`). Это же объясняет, почему **уменьшение шага не
помогало, а иногда вредило**: `beta = dt/(eta+dt)`, и чем меньше шаг, тем
сильнее `Dv` отстаёт от `D` и тем больше несёт удаляемый элемент.

## 4. Когезионные элементы UC6

Файлы: `cohesive_uc6.f` (закон), `e_c3d_uc6.f` (матрица жёсткости),
`resultsmech_uc6.f` (внутренние силы, состояние, вывод),
`extrapolate_uc6.f` (экстраполяция на узлы).

Подключён через **штатный механизм пользовательских элементов CalculiX** —
`*USER ELEMENT` / `*USER SECTION`; `userelements.f` и `usersections.f`
не менялись вообще (diff пуст, кроме года в копирайте). Добавлены только
три строки диспетчеризации по `lakon(2:3) == 'C6'` в `e_c3d_u.f`,
`resultsmech_u.f`, `extrapolate_u.f`.

```
*User Element, Type=UC6, Nodes=6, Integration Points=3, MaxDof=3
*User Section, Elset=INTERFACE, Material=COHESIVE, Constants=6
Kn, Tn0, Ts0, Gc, gmin, mu
*Depvar
4
```

### 4.1 Геометрия и кинематика

Шестиузловой **треугольник нулевой толщины**: узлы 1–3 — «минус»-сторона,
4–6 — «плюс», попарно совпадающие. Совпадение **проверяется**, а не
предполагается: начальный зазор больше `max(1e-10, 1e-8*sqrt(A))` —
это `*ERROR` (`cohesive_uc6.f:158`). Причина: определяющая переменная —
только скачок перемещений, и ненулевой начальный зазор был бы молча
проигнорирован.

Локальный базис: нормаль `n = (x2-x1) x (x3-x1) / |...|`, первый сдвиг
вдоль `x2-x1`, второй — векторное произведение. Площадь `A = |cross|/2`.
Знак нормального раскрытия задаётся **порядком узлов 1..3** —
это надо контролировать в сетке.

Скачок в локальном базисе:

```
delta = R * sum_i N_i ( u(i+3) - u(i) )
```

Интегрирование — **трёхточечная схема для треугольника** с весами `A/3` и
барицентрическими координатами `(2/3, 1/6, 1/6)` в циклической
перестановке (`cohesive_uc6.f:170`). Комментарий объясняет выбор: одна точка
на треугольнике нулевой толщины даёт **песочные (hourglass) моды**, три
точки точно интегрируют линейное поле скачка и его квадратичную энергию.

Матрица жёсткости — `K = sum_ip (A/3) B^T C B`, `B` строится со знаком
`-1` на узлах 1–3 и `+1` на 4–6 (`e_c3d_uc6.f:50-73`).

### 4.2 Смешанный режим: эффективное раскрытие

```
beta  = (Ts0 / Tn0)^2
deff^2 = <delta_n>^2 + beta * (delta_s1^2 + delta_s2^2)        cohesive_uc6.f:179
```

`<.>` — скобки Маколея: **сжатие не приводит повреждение**.

`beta` выбран не произвольно. Тяга:

```
t_n = g*Kn*delta_n           (delta_n > 0)
t_n =   Kn*delta_n           (delta_n < 0, полный контактный штраф)
t_s = g*Kn*beta*delta_s
```

Отсюда чистое растяжение даёт пик `Kn*d0 = Tn0`, а чистый сдвиг — пик
ровно `Ts0`. То есть потенциальная форма с одним `beta` воспроизводит
**две разные прочности** и при этом сохраняет **симметричную**
материальную касательную.

### 4.3 Билинейный закон и энергия разрушения

```
d0 = Tn0 / Kn            (раскрытие инициации)
df = 2*Gc / Tn0          (раскрытие полного разрушения)
dmax = max(dmax_hist, deff)               необратимость
D_backbone = df*(dmax - d0) / (dmax*(df - d0))      cohesive_uc6.f:190
```

Проверка `df > d0` — жёсткая ошибка при чтении свойств.

Работа, сопряжённая `deff`: так как `deff*d(deff) = q . d(delta)` с
`q = (<delta_n>, beta*delta_s1, beta*delta_s2)`, а `t = g*Kn*q`, то

```
t . d(delta) = g*Kn*deff*d(deff)  =  T_eff * d(deff)
```

и эффективная тяга на размягчающей ветви равна

```
T_eff(deff) = Tn0 * (df - deff) / (df - d0)
```

— **линейное размягчение**, площадь под кривой `= Tn0*df/2 = Gc`.

**Следствие, которое надо сказать в докладе явно: `Gc` в этой модели не
зависит от смешения мод.** Прочности Mode I и Mode II разные (`Tn0`, `Ts0`),
а энергия разрушения общая. Закон смешения типа Benzeggagh–Kenane
(`Gc(mode mix)`) здесь **не реализован**.

Итоговая деградация:

```
g = max(gmin, 1 - Dv)                     cohesive_uc6.f:203
```

### 4.4 Излом при закрытии трещины и его регуляризация

Нормальный закон **непрерывен** в `delta_n = 0`, но его **наклон
скачет** с `g*Kn` на `Kn` — множитель `1/gmin`. Это измерено на одном
facet напрямую: наклон в дальнем сжатии `999999` против `Kn = 1e6`, в
дальнем растяжении `1` против `g*Kn = 1`, **отношение 1e+06**.

`CCX_UC6_CONTACT_SMOOTH=<z>` размазывает переход по полосе проникания
`w = z*d0` (`cohesive_uc6.f:270-292`):

```
psi(u) = 0              u <= 0
         u^2/(2w)       0 < u < w          u = -delta_n (проникание)
         u - w/2        u >= w

t_n     = g*Kn*delta_n - (1-g)*Kn*psi(u)
dt/dd   = g*Kn + (1-g)*Kn*psi'(u)          psi' от 0 до 1 монотонно
```

Закон становится `C1`, наклон нигде не превышает `Kn`, и при `g = 1`
выражение **тождественно** сводится к `Kn*delta_n` — поэтому включение
регуляризатора побитово ничего не меняет там, где нет одновременно
повреждённой и закрытой фасетки (проверено: 542 попытки, 1283 итерации
Ньютона, `.sta` и `.damage` совпали побайтно).

На полной модели `s3rad` регуляризатор физику не двигает: момент
разделения `theta = 0.3411981` (острый закон) против `0.3418522`
(сглаженный) — **0.19 %**.

### 4.5 Консистентная касательная UC6

```
C = g*Kn*diag(1, beta, beta)  -  Kn * q  (x)  (alpha * dD/d(deff)) * q/deff

dD/d(deff) = df*d0 / ((df - d0) * deff^2)                cohesive_uc6.f:309
alpha      = dt / (mu + dt)      (вязкий множитель)
```

Поправка рангa 1 — **симметричная** (`q (x) q`), поэтому симметричный
солвер остаётся применимым. Она включается только когда точка
**нагружается** (`deff >= dmax - tol`), находится в процессной зоне
(`d0 < deff < df`) и ещё не легла на пол `gmin`.

### 4.6 Переменные состояния и вывод

`*DEPVAR 4`:

| слот | смысл |
|---|---|
| 1 | `dmax` — максимальное эффективное раскрытие за историю |
| 2 | `Dv` — вязкое повреждение |
| 3 | `D` — невязкая «опорная» кривая |
| 4 | флаг разрушения (0/1), ставится при `D >= 1 - 1e-12` |

В `stx` пишутся `t1, t2, t3, Dv, deff, dmax`; в `eei` —
`delta_n, delta_s1, delta_s2, Dv, deff, dmax` (`resultsmech_uc6.f:43-70`).
Слот 4 — единственное, что читает топологическая логика (`damstate.c:105`).

## 5. Нелокальная регуляризация: внутренняя длина

Файл `damnonlocal.f` (796 строк), переключатель `CCX_DAMAGE_NONLOCAL=<ell>`.

### 5.1 Зачем, если уже есть crack band

Это разделение, которое стоит подчеркнуть в докладе, потому что его часто
путают:

* **crack band** делает **диссипацию** независимой от размера элемента —
  и делает это правильно: на трёх равномерных сетках индикатор
  `L*sigma_y/(u_f*E)` масштабируется ровно как `L`;
* **ширины локализации** он не задаёт. Как только размягчение делает
  касательную неопределённой, краевая задача теряет эллиптичность, и полоса
  локализации имеет ширину ровно в один слой элементов — какой бы он ни был.

Измерено (E-83): те же три сетки совпадают **до пика** с точностью 0.94 %
и расходятся **после пика** на 73–89 %, причём посткритические кривые даже
не упорядочены по размеру элемента.

**Вязкость это не чинит.** При `eta = 1e-4` те же три сетки доходят до
`t = 1.0` вместо обрыва на `t = 0.32…0.35`, а кривые сдвигаются меньше
чем на процент: разрешимость — да, объективность — нет. Скоростной член
не заменяет длину, и его помощь **слабеет при измельчении**, потому что
полоса локализуется в меньший объём.

### 5.2 Интегральная форма (Pijaudier-Cabot — Bažant)

Приводящая переменная — приращение эквивалентной пластической
деформации — заменяется её взвешенным средним по окрестности радиуса
`2*ell`:

```
dp_nl(e) = sum_f w(d) V_f dp(f) / sum_f w(d) V_f
w(d)     = exp( -(d/ell)^2 )
```

**Объём элемента стоит в весе намеренно**: без него разрезание той же
окрестности на большее число элементов меняло бы среднее, и сеточная
зависимость просочилась бы обратно.

Соседи ищутся по сетке бакетов размера `rmax` (27 ячеек вокруг) и список
строится **один раз, по отсчётной конфигурации** — внутренняя длина есть
свойство материала и не должна «плыть» вместе с деформацией сетки.
Удалённые элементы (`ipkon < 0`) в среднее не входят: материала там больше
нет, нормировка потерю поглощает.

Каскад к остальному коду минимален: **вся остальная модель читает
регуляризованную переменную через один аксессор** `damnonlocalval`,
возвращающий один скаляр на элемент. Определяющий закон, ранг-1
касательная, терминальное удаление, откат и вся топологическая машинерия
не тронуты.

### 5.3 Неявная градиентная форма (Peerlings — Geers)

`CCX_DAMAGE_NONLOCAL_MODE=GRADIENT`:

```
ebar - div( ell^2 grad ebar ) = e
```

Дискретизация: узловая `ebar`, линейные тетраэдры, **сосредоточенная
масса**:

```
A_ab = delta_ab * V/4  +  ell^2 * V * (grad N_a . grad N_b)
f_a  = V/4 * e_elem
```

`A` симметрична, положительно определена и доминируется массой, поэтому
решается CG с якобиевым предобуславливателем — десятки итераций, без
построения разреженной структуры и без обращения к PARDISO
(произведение матрицы на вектор — цикл по элементам). Удалённые элементы
просто не вносят вклад, и это **правильное граничное условие на растущей
трещине**: среднее не должно диффундировать через поверхность, которой уже
нет.

Зачем вообще две формы: у интегральной памяти `O(N * (2*ell/h)^3)`.
На равномерной решётке это приемлемо, на градиентной сетке gmsh —
катастрофа: измерено **6.5 ГБ при `ell=0.15`, 20.8 ГБ при 0.30 и 58.4 ГБ
при 0.45** против 31.6 ГБ машины. У PDE-формы списка соседей нет вообще,
цена `O(nnz)` при любой градиентности.

### 5.4 Контрольный режим `FROZEN-LOCAL` — и честная оговорка

Это **не регуляризация**, а недостающее плечо эксперимента
(`damnonlocal.f:394-416`). Причина, по которой его пришлось сделать:

при `ell > 0` приводящая переменная обновляется **один раз за вызов
`calcdamagebase`** (то есть на предикторе и на коммите), а
`damageupdatepoint` читает это же значение на каждой итерации Ньютона.
Значит при `ell = 0` повреждение интегрируется **неявно внутри Ньютона**,
а при `ell > 0` — только между шагами. **Это смена схемы, а не запаздывание.**

Следствие: любое сравнение «локально против нелокально» в этом дереве
двигает **два фактора сразу** — внутреннюю длину и схему интегрирования.
`FROZEN` — та же расслоённая (staggered) схема без всякого усреднения и без
длины; если она одна уже даёт большую часть объективности, значит
объективность дала не длина. В докладе это честнее показать, чем умолчать.

### 5.5 Где именно нелокальность включается

Мест расчёта повреждения **два**, и оба должны видеть поле:
`calcdamagebase` (предиктор и коммит) и `damageupdatepoint`, который
`resultsmech` вызывает **поточечно внутри обновления напряжений**. Второе —
то, что реально ведёт отклик: патч только первого оставил ответ
**побитово равным локальной модели**, чем это и было обнаружено
(`calcdamage.f:952-965`).

## 6. Касательный оператор

### 6.1 Что не так с секущей

Базовый режим — симметричная секущая `g(D) * C_ep`. Это не производная
невязки: при активном размягчении `D` зависит от деформации, и полная
консистентная касательная имеет вид

```
C = g(D) * C_ep  -  sigma_eff (x) dD/d(eps)
```

Второй член — **ранг-1 и в общем случае несимметричный**.

### 6.2 Как он считается и собирается

* `dD/d(eps)` строится **конечными разностями** по шести компонентам
  `emec` с шагом `h = 1e-7*max(1,|emec_k|)`; вся точечная история и
  повреждение восстанавливаются после каждой пробы (`resultsmech.f:1120-1155`).
  При включённой вязкости используется `d(Dv)/d(eps) = beta * dD/d(eps)`.
* Сдвиговые компоненты домножаются на `1/2`, потому что `incplas` работает
  с **тензорными** сдвигами, а 21-элементное хранилище касательной — с
  **инженерными** (`resultsmech.f:1214`).
* `mafilldamas.f` добавляет только ранг-1 поправку поверх уже собранной
  симметричной части. Вклад элемента факторизуется в внешнее произведение
  двух векторов длины `3*nope`:

```
a(ii,i1) = F(i1,m) T(m,k) shpj(k,ii)
b(jj,j1) = F(j1,n) Q(n,l) shpj(l,jj)
s       += -weight * a (x) b
```

Так `e_c3d.f`, `anisonl.f` и 21-элементное хранилище констант менять не
пришлось.

Ограничения (проверяются, а не предполагаются): только C3D4, только
`nmpc = 0`.

### 6.3 Согласование с полом остаточной жёсткости

Тонкость, найденная структурным FD-зондом, а не рассуждением: на полу
`g = gmin` деградация **постоянна по `D`**, значит `d(sigma)/d(eps) = gmin*C_ep`
и ранг-1 член **тождественно нулевой**. `damjac` пишется раньше, чем
известно, включится ли пол, поэтому при включении пола его надо обнулить
(`resultsmech.f:1253-1275`), иначе `mafilldamas` соберёт поправку, которой
не существует. Симптом был такой: один узел элемента нёс относительную
ошибку якобиана `9.4e-3`, три его соседа — `4e-6`, и ошибка совпадала до
семи знаков при `h` от `1e-8` до `1e-6`, то есть это не ошибка усечения.

### 6.4 Известный дефект первого порядка

Около шага 92, где расчёт впервые режет шаг, отношение дефекта
линеаризации **постоянно** вместо `O(eps)`, линейная скорость Ньютона
совпадает с ним до шести знаков, а его величина отслеживает вязкий
множитель `dt/(eta+dt)` — то есть недостающий член связан **со скоростью
повреждения**. Это **не** ранг-1 член повреждения: его `dD/d(eps)` присутствует
(макс. 36.4, среднее 4.18 по 6850 элементам), а его действие на шаг Ньютона
составляет **0.27 %** от действия оператора — на два-три порядка меньше
дефекта. **Недостающая производная до сих пор не названа.**

## 7. Эрозия и топология: «что ещё несёт нагрузку»

Это то, чего в стоке нет совсем, и то, что на практике определяет,
доживёт ли расчёт до разрушения.

### 7.1 Терминальное удаление

```
D_trigger >= D_delete           (по умолчанию 0.999, CCX_DAMAGE_DELETE_D)
ipkon[i] = -ipkon[i] - 2
```

`nonlingeo.c:1471` (`damage_de13_mark_terminal`). Два существенных отличия
от стока:

* триггер читает **`Dv`, а не `D`**, когда вязкость включена (см. §3);
* удаление **пакетное** (до 64 элементов за проход, `DAMAGE_DE13_BATCH_MAX`)
  и **транзакционное**: момент срабатывания фиксируется в
  `trigger_value[]` в тот самый момент, когда элемент меняет топологию,
  потому что последующее переравновешивание на той же нагрузке меняет `dam`
  уже удалённых элементов, и история удалений (`.damage`) не должна
  восстанавливаться из текущего состояния.

### 7.2 Отсоединившиеся острова — `damfloat.f`

Поиск в ширину по выжившим элементам, засеянный **каждым узлом, который
держит граничное условие или входит в MPC**. Всё, что не достигнуто,
не имеет пути нагрузки к земле и помечается терминальным.

Почему это нужно: проверка «узел потерял все свои элементы» не видит
область, которая внутренне связна, но ни к чему не прикреплена — остров,
вырезанный трещиной. Симптом безошибочен: **поправка Ньютона порядка
размера образца в узле, далёком от фронта, и растущая вместо убывающей
невязка.**

Когезионные фасетки в обходе **участвуют**: целая фасетка — это настоящий
путь нагрузки, и игнорировать её значило бы объявить отсоединённым
нормально подпёртый островок гидрида.

Отдельный счётчик разделяет два физически разных удаления, которые раньше
печатались одним числом: когезионная фасетка, потерявшая объём с одной
стороны (уходит при `g = gmin*Kn`), и объёмный островок, потерявший все
пути (уходит с тем, что нёс).

### 7.3 Висячие узлы — `damdangle.f`

Узел, опора которого **упала до порога с большего значения** (было много
элементов, осталось `<= ndanglemax`, обычно один), — это осколок материала,
который нагрузку уже не передаёт. Он проходит обе предыдущие проверки:
элемент у него есть, и этот элемент через три другие вершины прикреплён к
земле. Узел, у которого опора **изначально** была маленькой (вершина на
одном элементе — в этой сетке их три штуки с самого начала), не трогается:
условие `norig > ndanglemax` обязательно.

Второй, независимый признак приходит **снаружи**, в `ihazin`: узел,
у которого элементов много, но собранная диагональ упала до `1.1e-4` от
неповреждённой (узел 158). Топологический тест его не видит; это суждение
может дать только тот, у кого есть собранный оператор (`damstate.c`, §7.5).

Отдельно **считается, но не удаляется** класс узлов, потерявших все
объёмные элементы и висящих на одних когезионных фасетках. Обычный
подсчёт опоры намеренно считает когезионный элемент опорой — что верно для
целой фасетки и неверно для отслоившейся, несущей `gmin*Kn`.

Измерено, а не угадано: в модели с надрезом и одним гидридом расчёт
зацикливается на `lambda = 0.3579` — шаги 401, 403, 405, 407 собирают одни
и те же три элемента (7007, 7038, 7101), все откатываются, все падают
одинаково. Узел 2003 принадлежит всем трём и падает с четырёх выживших
элементов до одного. Именно его солвер потом двигает на `0.90` при шаге
нагрузки `2.9e-6`. **Уменьшение шага здесь принципиально не помогает**:
каскад вызван удалением, а не нагрузкой — половинный шаг дал batch из
шести элементов, потом четырёх, потом трёх и дальше не улучшался.

**По умолчанию выключен** (`CCX_DAMAGE_DANGLE`, E-22): критерий не отличает
осколок от легитимного последнего элемента в узле и на мелкой сетке
удаляет всё.

### 7.4 `DEADALL` / `DEADSOLE`

`DEADALL` (`nonlingeo.c:1381`): узел, у которого **вся** живая опора мертва
(`g <` порог `CCX_DAMAGE_DEADALL`; по умолчанию механизм выключен, в
расчётах `s3rad` стоит `1e-2`) и которого **не держит ни одна когезионная
фасетка**, — его элементы удаляются. Мотивация из
измерения: на `m14_fine` узел 776 имел ровно один живой элемент, стоявший
на `D = 1.0000`; узел прошёл 9.63 мм, три других узла того же элемента —
0.44 мм, длиннейшее ребро выросло с 0.0974 до 9.809 — растяжение **101×**
на образце 4 мм.

Множество-кандидат берётся **снимком**: удаление элемента забирает опору и
у трёх его других узлов, и разрешать это здесь потребовало бы неподвижной
точки; следующий шаг подберёт остаток — как и всякий другой batch в этом
файле.

### 7.5 Суждение о потере пути нагрузки — `damstate.c`

Один владелец на одно суждение. Для каждого узла со **всеми тремя**
активными трансляционными степенями свободы берётся минимум собранной
диагонали и сравнивается с **его собственной** неповреждённой опорой
`diag0` (первое положительное значение, когда-либо увиденное, — вниз оно не
дрейфует):

```
узел мёртв, если  min_diag < g * diag0
```

Отношение безразмерно, медиана по сетке не нужна. Неположительная
диагональ — **другой объект** (узел на нисходящей ветви), обрабатывается
отдельно и по умолчанию мёртвым не считается.

Модуль **отказывается вооружаться, если его самотест не прошёл** — та же
дисциплина, что у `lsladder.c`. Самотест пинует в том числе исторический
дефект: `if((dmin<0.)||(ad<dmin))` перестаёт быть минимумом, как только
появляется одно отрицательное значение, и хранит **последнее** отрицательное,
а не наименьшее (кейс F).

Зачем: вторая «стена» на `s3rad` была ровно зазором между двумя
потребителями этого суждения. AUTOSPC знал, что узел 1246 потерял путь
нагрузки, и сообщал об этом **норме перемещений**; **норма сил** — та, что
фактически ветировала шаг, — не знала. Закрытие зазора
(`CCX_DAMAGE_AUTOSPC_FORCE=1`) перевело расчёт с шага 554 / `theta=0.2556`
на 930 / `theta=0.5575` при побитово идентичной предыстории (1147 попыток).

Механика стены полезна для доклада как иллюстрация: пиковая невязка сидела
на **осколке, который держал ОДИН живой объёмный элемент, при всех шести
своих когезионных фасетках разрушенных и открытых**. Уравновесить его
требует перемещения порядка единицы против захвата, прошедшего 0.2556,
поэтому невязка падала на 0.1 % за итерацию. Эта компонента наследовалась
каждым следующим шагом и накапливалась — 15.7, 50.4, 74.9, 94.5, 105.7 %
допуска на шагах 551–555, — **пока `dtheta` сжимался в 48 раз**. Уменьшение
шага в 48 раз сделало равновесие в 6 раз хуже, потому что несжимаемая часть
невязки шагу не пропорциональна.

### 7.6 Критерий разделения образца — `damconnect.f`

Трещина **завершена**, когда никакая цепочка выживших элементов больше не
связывает две границы:

```
растяжение   Face_X0        <-> Face_XL
Ламе         InnerPressure  <-> OuterRadius
```

Удалённые элементы (`ipkon < 0`) пропускаются, так что тест видит ровно ту
несущую топологию, которую видит сборка. Просто деградированные элементы
**проводят**: ненулевая жёсткость — это путь нагрузки, назвать её разрывом
было бы модельным решением, а не топологическим фактом.

### 7.7 Самый серьёзный дефект физики, и он должен быть в докладе

**Разрушенная когезионная фасетка никогда не исчезает.** `cohesive_uc6.f`
прижимает `g = max(gmin, 1 - Dv)` при `gmin = 1e-5`, а терминальное удаление
сканирует **только `C3D4`**. Значит полностью отслоившаяся фасетка вечно
читается как путь нагрузки.

Последствия, измеренные на `s3rad`:

| | |
|---|---|
| металл теряет связность захват-к-захвату на шаге | **753**, `theta = 0.3411981` |
| расчёт продолжается до | шага **931**, `theta = 0.5575` |
| то есть идёт за пределом разделения ещё | **+63 % перемещения захвата** |
| что решается в этой зоне | две разделённые половины, соединённые **451 фасеткой**, 322 из них на остаточном полу |
| реакция захвата при `theta = 0.4064` | **0.056 % от пика** |

Это худший дефект в дереве именно потому, что он даёт **не неверное, а
правдоподобное** число. Он изготовил «третью стену», которая была
сходимостной неудачей конфигурации, переставшей быть образцом за 178 шагов
до того.

Два уровня лечения, и они не альтернативны:

* **корень** — дать полностью разрушенной фасетке действительно
  удаляться (`CCX_DAMAGE_FACET_DELETE`) или перестать считать её
  связностью; тогда половины становятся свободными телами, матрица
  сингулярна, и расчёт **обязан** остановиться — модель узнаёт об этом сама;
* **страховка** — `CCX_FRACTURE_TERMINATION` / `CCX_FRACTURE_DEADFACET`
  уже умеют детектировать потерю пути нагрузки, читая слот 4 состояния
  UC6.

## 8. Индикатор корректности постановки (`damsnapcheck.f`)

После инициации закон деградирует элемент на пластическом перемещении
`u_f`, поэтому модуль размягчения, который «видит» элемент, порядка
`sigma_y * L / u_f`. В сравнении с модулем упругой разгрузки `E`:

```
r = L * sigma_y / (u_f * E)
```

`r > 1` означает, что собственная ветвь размягчения элемента круче упругой
разгрузки, которую он может обеспечить, — **локальный snap-back**.

Честная формулировка (она есть в самом коде): это **индикатор, а не
доказательство** чего-либо о глобальной задаче. Конструкция с такими
элементами может найти равновесие, перераспределившись в более жёсткие
соседние; зависит это от окружающей сетки, граничных условий и пути
нагружения — ничего из этого скаляр не видит. Что `r > 1` предсказывает
надёжно — что консистентная касательная обнажит там неопределённый
элементный оператор.

Проверка печатается в начале расчёта и **ничего не меняет**.

## 9. Управление траекторией (нужно, чтобы физика вообще досчиталась)

Квазихрупкое разрушение с эрозией — это последовательность предельных
точек и snap-back'ов. Управление перемещением на них останавливается,
поэтому в модуле есть продолжение по параметру.

**Диссипационная арк-длина** (`pathfollow.c`) — ограничение Гутьерреса
в инкрементной форме Верхосела:

```
f_hat := -dR/dlambda                       (фиксируется на шаг)
dG(u,lambda) = 1/2 ( lambda_n * f_hat^T u  -  lambda * f_hat^T u_n )
g = dG - tau = 0
```

Производные точны, потому что `f_hat` заморожен. Расширенная система
решается стандартным двухрешенческим (Riks) разложением.

Почему не геометрическая арк-длина Крисфилда/Рикса: сферическое
ограничение `|du|^2 + psi^2 dlambda^2 = dl^2` меряет **весь** вектор
перемещений, а после локализации норма доминируется **разгружающимся
упругим объёмом**, то есть ограничение перестаёт видеть механизм ровно
там, где он нужен.

**Смешанно-модовая координата управления** (`crackcontrol.c`) — потому что
на этой задаче диссипационная форма вырождается: при управлении
перемещением на локализованной когезионной трещине `f_hat` живёт на
степенях свободы у нагружаемой грани, блок с этой стороны после разрушения
движется как жёсткое целое, и `f_hat^T u` остаётся пропорциональна
`lambda`, что бы ни делала трещина. Измерено на `test/pathfollow/cohesive.inp`.

Взамен управляют тем, вдоль чего сам закон продвигается, — `deff`:

```
q = (<dn>, beta*ds1, beta*ds2),   m = q/deff   (заморожено на состоянии)
phi(u) = sum_ip  w_ip * m_ip . [[u]]_ip
```

`deff` положительно однородна степени 1, поэтому по тождеству Эйлера
`m . delta = deff` **точно** в точке заморозки, а `m` — точный градиент.
Ограничение записывается **инкрементно** от закоммиченного состояния,
поэтому переопределение функционала между шагами безвредно по построению —
это же чинит дефект устаревшего вектора, когда число уравнений меняется
после удаления элементов.

Веса не произвольны. Для билинейного закона диссипация на единицу
продвижения `dmax` **постоянна**:

```
dPsi/d(dmax) = 1/2 * Tn0 * df/(df - d0)
```

поэтому с `w_ip = (A_ip/3) * 1/2 * Tn0 * df/(df-d0)` на нагружающихся
фасетках и `0` в остальных `phi` **и есть когезионная диссипация** — то же
ограничение Гутьерреса, но записанное для трещины, а не для границы
нагружения, и без слепого пятна.

Почему ограничение «только нагружающиеся точки» — это определение, а не
порог: разгружающаяся точка **не диссипирует ничего**, её повреждение
заморожено, тяга идёт по секущей к началу. Измерено на `s3rad`, шаги
160–175:

| | было | стало |
|---|---|---|
| процессная зона | 11002 т.и. | 10874 |
| из них нагружаются | 4716 | 4105 |
| среднее `deff` по зоне | 4.007e-03 | 3.924e-03 **(убывает)** |
| среднее `deff` по нагружающимся | 6.215e-03 | 6.347e-03 (растёт) |

Среднее по зоне идёт **назад**, потому что точки уходят в разрушение
быстрее, чем выжившие раскрываются: ограничение на нём просило бы
продвигать величину, которая физически отступает.

Результат на чистых бенчмарках: на Mode-I модели штатное управление
перемещением останавливается в предельной точке, а COD-управление проходит
**798 последовательных посткритических шагов** с реакцией на замкнутой
билинейной ветви. На смешанно-модовом бенчмарке (наклонная когезионная
плоскость) штатное управление останавливается после 62 шагов, а
смешанно-модовое проходит **2400** шагов с реакцией на замкнутой форме до
`5e-07` и невязкой ограничения `2e-18`; то же — при 36 % и 90 % сдвига.

Что этот результат **не** доказывает — что досчитается сам `s3rad`.

## 10. Параметры целевой модели `s3rad`

Двухфазный диск C3D4, циркониевая матрица + гидридная пластина, интерфейс
из 5400 фасеток UC6 (2724 продублированных узла), растяжение по `x`.

```
*Material, Name=ZR                     *Material, Name=ZRH
*Elastic  108800., 0.335               *Elastic  130000., 0.33
*Plastic  500 ... 720 МПа              *Plastic  600 ... 720 МПа
                                        (очень крутое упрочнение: 600->720
                                         за 1 % деформации — хрупкая фаза)
*Damage Initiation, Criterion=Ductile, Evolution=Displacement, Npoints=6
ZR :  omega_lim=1.0  u_f=0.0150   eps_f(eta): (0,0.300) (0.33,0.120) (0.50,0.070)
                                              (0.67,0.0425) (1.00,0.025) (1.50,0.015)
ZRH:  omega_lim=1.0  u_f=0.0040   eps_f(eta): (0,0.120) (0.33,0.070) (0.50,0.045)
                                              (0.67,0.028) (1.00,0.015) (1.50,0.010)

*User Section (UC6):  Kn,      Tn0,   Ts0,   Gc,    gmin,  mu
INTERFACE_SEED     :  200000., 275.0, 240.0, 2.000, 1.e-5, 1.e-4
INTERFACE_REGULAR  :  200000., 300.0, 260.0, 2.400, 1.e-5, 1.e-4
```

Отсюда для обычной фасетки: `d0 = Tn0/Kn = 1.5e-3`, `df = 2Gc/Tn0 = 0.016`,
`beta = (260/300)^2 = 0.751`. Гидрид в 3.75 раза «хрупче» матрицы по `u_f`
и почти вдвое — по локусу разрушения.

Фронт на этой модели **измерен, а не предположен**: 63 % точек
интегрирования процессной зоны несут более половины `deff^2` в сдвиге,
39 % — более 90 %. То есть нормальное раскрытие **не является** там
координатой процесса, что и было причиной ввести смешанно-модовое
управление.

## 12. Ограничения — что сказать честно

1. **`Gc` не зависит от смешения мод.** Прочности Mode I/II разные, энергия
   одна. Закона Benzeggagh–Kenane нет.
2. **Объёмная эволюция реализована только для C3D4.** Для других типов
   элементов — явная ошибка, а не молчаливое падение на сток.
3. **Касательная нелокальной модели остаётся локальной** — стандартный
   размен для этого семейства: стоит итераций Ньютона, не корректности.
4. **Нелокальное поле обновляется расслоённо** (§5.4) — при `ell > 0`
   повреждение перестаёт интегрироваться неявно внутри Ньютона. Это смена
   схемы, и всякое сравнение «локально/нелокально» в этом дереве двигает
   два фактора сразу.
5. **Разрушенная когезионная фасетка не удаляется** и вечно читается как
   путь нагрузки (§7.7) — самый серьёзный дефект, даёт правдоподобные, но
   бессмысленные результаты после разделения образца.
6. **Деградация по умолчанию не разделяет растяжение и сжатие** в объёме,
   хотя когезионный закон это делает; вариант есть, но он выключен, и в
   нём приходится ограничивать `nu'`, иначе линейный тетраэдр запирается.
7. **Недостающая производная в касательной не названа** (§6.4): дефект
   первого порядка отслеживает вязкий множитель, но ранг-1 член повреждения
   на два-три порядка мал, чтобы его объяснить.
8. **139 переключателей окружения**, 63 не описаны нигде, кроме строки,
   которая их читает, 122 не выставляются ни одним тестом дерева
   (`docs/SWITCHES.md`, счётчики генерируются, а не оцениваются). Для
   доклада это стоит назвать своим именем: комбинаторное пространство, про
   которое никто не может сказать, что делает произвольная комбинация.
9. **Воспроизводимость только внутри фиксированного числа потоков.**
   `MKL_CBWR=COMPATIBLE` фиксирует набор инструкций, но не порядок
   редукции. Два расчёта, совпадавшие 482 попытки, разошлись на 483-й по
   счётчику итераций 6 против 5 и через двадцать шагов были на разных
   стенах. Частично это неустранимо: квазихрупкое разрушение с эрозией —
   последовательность топологических скачков, и разница `1e-16` решает, с
   какой стороны порога окажется точка интегрирования.
